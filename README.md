# E_coder

个人编程辅助 Agent。Python 3.12 + FastAPI + SSE + SQLite，Vue 3 + Vite 白色工作台，uv 管理后端依赖。

## 启动

克隆仓库后，先从 `.env.example` 创建本机 `.env`，填写自己的模型配置，或启动后在“连接与配置”中设置。真实密钥、本地数据库、用户工作文件、依赖与虚拟环境都不包含在仓库中；不要把密钥放入前端代码或 `VITE_*` 变量。技能的 `runtime.conf` 是本机路径配置，不参与版本控制；换机器时通过 `load_skill` 返回的运行时和资源目录调用脚本，或创建自己的配置。

```powershell
cd E_coder
.\start.ps1
```

访问 http://127.0.0.1:8765。模型配置可在侧栏“连接与配置”中编辑并即时保存；密钥保存在本机 .env，不回显到前端。

## Vue 前端开发

当前界面已重构为 Vue 3 单文件组件与 Composition API。构建产物随项目提供，日常仍运行 `start.ps1`，无需额外启动 Node 服务。

修改前端时使用 Node.js 22.12+，在 `frontend/` 内运行 `npm ci`、`npm run dev`，开发入口为 http://127.0.0.1:5173/static/vue/ ，代理至 8765 后端。完成后运行 `npm test`、`npm run build`、`npm run deploy`，将构建部署到 `static/`。前端依赖仅安装于项目的 `frontend/node_modules`；API Key 只在后端配置，不放进 Vite 环境变量。

会话/SSE 状态集中在 `frontend/src/composables/useWorkbench.js`，页面拆分为聊天、执行面板、工具技能、详情弹窗、连接配置和存储管理组件；详细结构与测试说明见 `frontend/README.md`。

## 连接文件夹与上传文件

文字直接在输入框中输入。图片、文件入口上传单个或多个附件；文件夹入口用于连接本机目录，支持粘贴绝对路径或打开本机目录选择器。

- 选择文件夹只在数据库保存路径，不复制文件、不读取全部内容。文件面板仅列出当前层，点击目录逐层浏览；Agent 通过 list_files、read_file、search 按需读取内容。
- 连接本地文件夹后，工具和命令直接使用原目录；审批通过的修改保存到原文件。空文件夹也可以连接，连接关系在重启后保留。
- 未上传文件或文件夹时，使用项目根目录下自动创建的 `default_workspace/`，未上传的会话共用此目录。
- 附件独立保存在会话上传目录，不会自动复制进所连接的本地文件夹。原默认目录中的文件保留，页面不展示固定路径栏。
- 已有附件的会话也可连接或更换本地文件夹；旧附件保留实际存储位置，预览、下载和按需读取不受影响。拖入文件夹会打开目录连接窗口，不会遍历并上传文件。
- 当前消息附件以卡片展示，可从本条消息移除；移除卡片不会删除已上传文件。
- “文件”面板展示上传文件和 Agent 新生成的文件，支持添加到消息和下载修改后的内容。
- PNG、JPEG、WebP、GIF 可以作为图片输入交给模型；每条消息最多 4 张、每张 5 MB。历史图片需要时可从文件面板重新添加。
- 文本/代码可通过文件工具直接读取。其他二进制文件支持保存和下载，PDF/Office 等格式需额外解析工具，不能直接当作 UTF-8 文本读取。

图片与单独文件上传会创建副本；连接本地文件夹则直接使用原文件，没有复制过程。选定目录本身不会发给模型，模型调用文件工具后才会获得对应内容。

每批最多 1000 个文件、100 MB；单文件 20 MB，每个会话累计上传 250 MB。同名文件不会自动覆盖。上传会跳过 .git、node_modules、.venv、内部目录及 .env 环境文件。任务运行时不能上传，上传期间不能启动或删除任务。

## Agent 能力

15 个结构化工具、独立上下文子 Agent、Cron 定时任务、按需 Skills、文件 diff/命令审批、任务依赖、SSE 流式交互、执行事件回放、上下文按完整轮次整理。专用文件工具与命令使用当前会话生效的本地目录、默认目录或上传目录；命令仍需逐次审批，默认在 Windows AppContainer 沙箱中执行。

## Sub-agent 委派

主 Agent 可调用 `sub_agent(prompt, max_steps=30)`，在全新的对话上下文中执行明确子任务。例如发送：“请用 sub_agent 检查当前项目的测试结构，返回相关文件和结论，再由你汇总。”是否委派由模型选择；工具调用会显示在执行记录中。

- 子 Agent 不继承父对话、备忘录、任务清单或历史图片；主 Agent 必须在 prompt 提供任务背景、约束和必要文件路径。它可读取当前会话允许访问的附件文件。
- 使用同一模型、同一工作目录，同步执行并等待结果；共享文件系统，不是独立进程或沙箱。子 Agent 的写入、编辑、命令沿用现有逐次审批和快照检查。
- 子 Agent 仅有文件、搜索、命令和技能加载工具，不能继续委派或修改主会话的任务清单与备忘录；后端也会拒绝越权工具调用。
- 中间模型消息仅存于子循环内存，中间文本和工具事件保留在执行记录中，不加入父对话。只有最终结论（最多 16,000 字符）或失败结果成为主 Agent 的工具结果。
- 每次委派最多 30 轮且不超过主循环的单次步数上限；主循环和每个子循环分别计步。子上下文超过字符限制会停止；达到上限会明确返回未完成。点击“停止”会取消正在执行的子 Agent 和待审批请求，已执行的修改保留。
- 模型调用次数和 Token 统计包含子 Agent；当前版本为单层串行委派，不支持并行团队或跨运行恢复。

## Hooks 与权限

运行时提供 `UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop` 四个 Hooks，支持可信 Python 代码注册同步或异步回调。默认 `permission_hook` 在 `PreToolUse` 中校验参数、子 Agent 工具白名单和路径，并处理 diff/命令审批；主 Agent 和子 Agent 共用。前置 Hook 返回阻止原因或失败时不会执行工具；后置 Hook 失败会保留已发生的工具结果。Stop Hook 可要求继续验证，但仍受循环上限约束。详细接口见 `docs/architecture.md`。

## 定时任务

参考 learn-claude-code/s12，实现 `schedule_cron`、`list_crons`、`cancel_cron`。可在对话中说“每天上午 9 点检查项目待办事项并汇总”，也可打开执行面板的“定时任务”页，填写表达式和任务内容、查看队列或取消。

时间固定为北京时间（`Asia/Shanghai`），五段依次为“分钟 小时 日 月 星期”，星期日为 0。支持 `*`、`*/N`、数字、范围和逗号列表；日和星期同时受限时按任一匹配触发。例：`0 9 * * *` 每天 9 点，`*/5 * * * *` 每 5 分钟，`0 9 * * 1-5` 工作日 9 点。

- 默认 `recurring=true, durable=true`。`recurring=false` 在下一次匹配时交付一次；`durable=false` 的任务仅存在于当前进程内存中。持久任务及待交付状态保存到 SQLite 的 `cron_jobs` 表。
- 到点先排队，再等当前会话的运行或上传结束；同一会话串行，不同会话可各自运行。一个任务尚在排队时，重复到期会合并；同一分钟不会重复入队，队列按到期先后交付。
- 模型首次成功响应表示“已交付”，不表示工作已经完成。首次响应前失败会保留任务并在 60 秒后重试；保留每次运行的审计记录。重启恢复待交付任务，采用至少一次交付，故故障边界上可能重复。
- 服务关闭时不执行，不补跑停机期间错过的时点。浏览器可以关闭，但 E_coder 后端进程必须运行。任务使用触发时本会话生效的目录和模型配置。
- 定时回合仍走 Hooks；写入、编辑和命令通过网页审批，未批准则超时拒绝，不会自动放行。点击“停止”只停止本次运行；取消定时任务才会移除后续触发和排队项，已启动的运行需另行停止。删除会话会清除其定时任务。

开发接口：`GET/POST /api/sessions/{session}/crons`、`DELETE /api/sessions/{session}/crons/{job_id}`。调度器随 FastAPI lifespan 启停，导入模块不会启动调度。可用 `.\.venv\Scripts\python.exe tests/live_cron_smoke.py` 执行真实 API 的单次后台交付验证；使用临时数据库和合成文本，会消耗模型用量。

## Goal 目标模式

参考 learn-claude-code/s17：主模型不再调用工具，只表示本轮想停止；目标是否完成由另一次独立、无工具的模型调用依据证据判断。未满足条件时，判断理由会送回当前循环，自动继续执行。普通聊天保持原来的行为，不会自行创建 Goal。

```text
/goal 修复登录模块，直到 pytest tests/auth 退出码为 0，且不修改测试文件
/goal
/goal pause
/goal resume
/goal clear
```

设置新条件会替换旧目标并立即开始，需等当前运行结束或先暂停。单独 `/goal` 查看状态，不调用模型。`pause` 暂停并保留条件；`resume` 恢复执行；`clear` 清除约束并停止该目标的当前运行（`stop/off/reset/none/cancel` 为清除别名）。执行面板的“目标”页也提供设置、进度、暂停、恢复和清除入口。

- 独立判断器使用同一已配置模型的另一段请求，工具列表为空，只输出严格的 `ok/reason/impossible` JSON；不会执行命令，也不把主模型没有工具证据的完成宣称直接视为成功。判断器不是测试框架，真实验证仍由主 Agent 调用工具完成。
- Goal 是会话级 `Stop` Hook；子 Agent 的结束不会触发父目标验收，子 Agent 调用用量计入目标。定时回合不会接管同一会话中无关的用户目标，仍按自己的 prompt 执行。
- 没有额外默认 Token 预算。每次运行沿用 `ECODER_MAX_STEPS`；连续未达标上限由 `ECODER_GOAL_BLOCK_CAP` 控制（默认 8）。达到任一上限时停止自动继续，保留未完成目标，用户决定是否恢复。
- 判断器调用失败或 JSON 无效时停止自动继续，不宣称成功；无法完成时保留原因。使用量区分主/子 Agent 与判断器，按每次请求的累计 usage 快照取最大值，只统计接口实际报告的 Token。
- 目标条件、状态、次数和用量保存到 SQLite 的 `goals` 表，事件进入原有 SSE。服务重启保留目标并标为中断，不会自动恢复执行；用户恢复后继续。所有文件和命令操作仍走权限 Hook 和原有审批。

API：`GET/POST /api/sessions/{session}/goal`、`POST /api/sessions/{session}/goal/control`（`pause/resume/clear`）。可用 `.\.venv\Scripts\python.exe tests/live_goal_smoke.py` 验证真实主模型读取临时文件、独立判断器验收的完整流程；仅使用合成文本，会消耗模型用量。

## 数据存储

.ecoder/state.db 保存会话、聊天、执行事件、任务、备忘录、上传文件元数据和 session_workspaces 目录连接记录。新附件统一保存在 .ecoder/uploads/<会话ID>/，uploads.root 记录各附件的实际目录，以兼容旧版保存在本地文件夹中的附件。文件工具仅额外允许本会话明确上传的附件文件路径，不开放附件父目录或其他会话的目录。图片 Base64 仅在模型请求时组装，不重复保存到聊天数据库。

删除最近任务会永久清除数据库中的会话及关联记录，包括上传索引和目录连接记录，不提供恢复；本机工作文件不随聊天记录删除。

## 存储管理

侧栏“存储管理”展示上传附件和默认工作区的文件大小、数量与占比，支持按位置筛选、搜索文件或会话、按页选择和批量永久清理。已删除会话遗留在上传目录中的文件会单独标出，可直接选择清理，每次最多 500 个文件。

删除前会显示所选文件及预计释放空间；清理会移除文件字节和对应的附件索引，保留聊天记录。历史消息中的失效附件显示“已清理”。已连接的原始项目目录仅显示引用路径，不纳入清理。任务运行或上传期间不能清理，文件发生变化后需要刷新重新选择；链接指向的内容不会被删除。

统计范围为上传目录和默认工作区内的文件大小，不包含会话数据库。单次最多扫描 20,000 个文件，达到上限时界面会提示当前为部分统计，清理后可继续刷新管理。

## 带脚本的 Skills

技能默认安装到 **E_coder 项目自身的 `skills/`**，与当前连接的用户工作目录无关。`skill-installer` 的运行参数由 E_coder 动态生成；即使直接运行安装脚本且不传 `--dest`，也会使用本项目的目录，不受 `CODEX_HOME` 影响。命令执行时会注入 `ECODER_SKILLS_DIR`；显式 `--dest` 可覆盖默认位置。技能列表的“已安装”标记也读取同一目录。旧会话的技能加载结果会在下一次模型请求中刷新。

复制到 `skills/<名称>/SKILL.md` 的技能会自动发现。`load_skill` 返回说明正文、技能绝对目录、资源索引、当前 Python/Node.js 路径以及可选的 `runtime.conf` 配置。Agent 需要使用配套脚本时，通过 `run_command` 的 argv 数组调用完整路径，并保留执行审批。技能中的普通文本资源可以通过 `read_file` 只读访问；环境密钥文件与越界链接不能读取，也不会因此开放技能目录写权限。

`anysearch` 使用本机 Node.js CLI，无需 Python requests 依赖。其 `runtime.conf` 保存当前电脑的 Node 可执行文件及脚本参数；移动项目或更换电脑后需更新其中的路径。复制技能不会自动安装依赖或把说明中的外部工具名注册成内置工具。需要鉴权的服务应按各技能说明配置自己的密钥，模型 API Key 不会自动提供给技能脚本。

技能索引直接包含项目内的目录及已配置的启动参数，避免 Agent 扫描外部个人技能目录。继续旧会话时，模型请求中的历史 `load_skill` 结果会从本项目当前技能重新生成，使运行时配置更新后立即生效；数据库中的原始调用记录仍保留，不会改写历史。

## 命令沙箱

以前的路径校验和 permission Hook 只限制专用工具，批准后的任意命令能访问主机。本版保留审批，并将 `run_command.execution_mode` 默认设为 `sandbox`：

- Windows AppContainer 不授予网络能力；临时工作区和运行时副本隔离于用户目录，主机原目录的 ACL 和完整性标签不修改。系统公开给 AppContainer 的资源仍可能可读，这不是虚拟机或完全不可见的文件系统。
- 工作区复制时排除 `.env`、`.env.*`、`.git`、`.venv`、`node_modules`、`.ecoder`、`.tools`、`__pycache__`，拒绝符号链接/目录联接等重解析点。附件和技能使用临时副本，只有工作区普通文件允许回写。
- 子进程只继承指定的标准输入输出句柄和最小环境，不继承模型密钥。Python 使用本项目运行进程的解释器及依赖副本；其他应用可能因为依赖不完整而无法在沙箱启动。绝对工作区/技能/附件路径参数映射到副本；内嵌脚本中的路径不重写，脚本请使用相对工作区路径。
- Windows Job Object 在恢复主线程前绑定，限制 16 个进程、单进程 512 MB、总计 1 GB 内存。超时（最多 120 秒）、取消、退出后终止全部后代进程。输出显示最多 24 KB，超过 2 MB 终止。工作区输入/回写限 128 MB、6000 文件；这些是扫描上限，并非磁盘写入配额。
- 仅退出码为 0 时同步新增、修改和删除的文件；非零退出、超时、取消丢弃改动。先校验全部差异及主机原文件快照，发现并发修改就拒绝同步；同步不是跨文件事务，磁盘等异常仍可能导致部分文件已提交。空目录不单独同步。
- 下载依赖、搜索联网、安装 Skill、访问被排除目录时，可明确请求 `execution_mode="host"`。审批卡会显示“主机执行”，该模式使用当前用户权限和网络。沙箱不可用时直接报错，绝不会静默降级。非 Windows 平台目前不提供此原生后端，主机模式仍须审批。

实现位于 `ecoder/sandbox.py`（副本与差异同步）和 `ecoder/winbox.py`（AppContainer、句柄白名单、Job Object）。`/api/status.sandbox` 报告默认模式与平台支持；`supported` 仅表示 Windows 平台，单次启动仍可能因系统策略而失败。

## 可读的定时任务

前端默认选择每天、周一至周五、每周、固定间隔或仅执行一次，再选择时间；列表显示中文说明。周一至周五不处理节假日调休。固定间隔按整点对齐；单次任务在所选时间的下次分钟匹配时执行，时间已过则为明天，不支持指定日期。高级选项保留原五段式 Cron，后端格式及已有任务兼容。


## 成功经验库（参考 ACE）

执行面板新增“经验”。选择已完成的轮次，勾选“我已确认这一轮实现了目标”，点击“提取成功经验”。系统使用独立的无工具模型请求反思执行记录，输出标题、适用条件、可复用策略及真实工具事件 seq；不接受失败/取消轮次或不存在的证据。普通 completed 只是结束信号，不自动认定成功。反思会使用已配置 API，最多 90 秒、每次 3 条；记录有长度上限及基础密钥脱敏，但仍请勿用包含隐私的记录提取。

SQLite `experiences` 保存项目经验、来源轮次和证据；按工作目录隔离并在同一目录的会话间复用。确定性的增量整理按规范化适用条件和策略精确去重，同一来源重复提取不增加确认数。后续任务根据适用条件/标题的关键词重叠检索最多 5 条已启用经验（最多读取最近 200 条），作为不可信历史参考注入上下文；不覆盖本次用户指令和审批。可以停用/重新启用经验。当前不是向量检索、完整 ACE 训练框架，也不更新模型权重；不会自动为所有历史会话调用付费模型。删除来源会话时移除该会话的经验来源证据；仍被其他会话引用的共享经验保留，无剩余来源的经验删除。

接口：`GET /api/sessions/{id}/experiences`、`POST .../experiences/extract`（run_id, confirmed）、`PATCH .../experiences/{experience_id}`（enabled）。实现：`ecoder/learning.py`。可运行 `tests/live_learning_smoke.py` 使用真实模型反思合成记录。

## 界面预览与组件标注（参考 Agentation）

执行面板新增“界面预览”。可点击“将生成界面的要求加入输入框”，补充具体界面需求并发送；Agent 通过现有写入/命令工具生成页面，仍需审批。静态页面选择 `index.html`，Vue/React 项目沿用原结构并先构建，再选择 `dist/index.html`。这不是开发服务器代理，不自动执行 npm install 或主机命令。

打开预览后可切换自适应、390px 手机或 768px 平板宽度。标注模式中点击 DOM 元素，记录 CSS 选择器、文本、矩形、视口，以及可选 `data-component` / `data-source` 提示；填写修改要求并保存。批量“提交待处理标注给 Agent”会开启当前会话新一轮修改，要求先定位真实源码，按原审批机制执行。完成后刷新构建产物、检查效果并标记已验收，或忽略标注；不会仅凭 Agent 自述自动标记解决。标注存在 SQLite `annotations`，提交时检查入口 HTML 内容哈希，页面已变则拒绝旧标注。CSS/JS 单独变化不在此哈希检测范围内。

预览使用无 allow-same-origin 的 sandbox iframe，父页面验证消息来源窗口、opaque origin 及随机令牌；令牌按会话/工作区限定并在 30 分钟后过期。响应 CSP 限制资源到专用静态预览端点，阻止嵌套页面、表单和普通外部接口连接。它不是应用测试环境或网络隔离虚拟机，请只预览可信项目；第三方 CDN、外部 API、服务端模板、开发服务器 HMR 和完整框架组件树映射不支持。组件提示是查找线索，不保证能精确映射源码；优先给关键元素添加 data-source。支持相对资源及入口 HTML 的根路径资源引用，动态脚本内的绝对路径等可能需要以相对 base 重新构建。

预览接口：`POST .../preview`（entry）返回令牌化 URL；`GET/POST .../annotations`、`PATCH .../annotations/{id}`（resolved/dismissed）、`POST .../annotations/submit`（ids）。实现位于 `ecoder/preview.py`、`preview_bridge.js` 和 `feature_routes.py`；前端为 ExperiencePanel / PreviewPanel。借鉴 Agentation 的结构化视觉反馈流程，未复制或捆绑其 React 组件；参考 ACE 的 Generator/Reflector/Curator 思路，由原有 Agent 执行、独立模型反思、确定性合并器整理。

参考： https://github.com/ace-agent/ace 、 https://github.com/benjitaylor/agentation


## 可选操作权限

输入框内发送按钮左侧的权限下拉框可选择“逐次审批”（默认）或“放开权限”，选中后立即保存，对所有会话、子 Agent、Goal 和定时任务生效，写入本机 .env 的 ECODER_PERMISSION_MODE，重启后保留。任何会话仍在运行时禁止切换。

逐次审批模式保留原有 diff/命令确认和默认沙箱执行。放开权限模式自动批准文件写入、编辑及命令，命令统一使用当前系统用户的 host 权限，可访问文件和网络；自动放行记录为 permission_auto_allow，仍保留工具执行结果、文件快照校验、参数校验和子 Agent 工具白名单。专用文件工具继续按工作区定位文件，工作区外操作可使用主机命令。停止按钮仍可停止任务。

接口：POST /api/permissions，JSON 为 {"permission_mode":"approval"} 或 {"permission_mode":"full"}；GET /api/status 返回当前 permission_mode。


## 清空消息显示

聊天顶部的“清空显示”只隐藏当前已显示的消息，不修改前端 messages 列表、后端历史或模型上下文，也不清除任务、审批和执行记录。新消息正常显示；“恢复显示”、刷新页面或重新进入会话可恢复全部消息。运行中的旧消息继续隐藏，新生成的消息仍会显示。此操作不发送删除请求。


经验管理按任务需求和北京时间选择来源，选中后可核对原始需求、最终回复、工具结果；每次更换任务需重新确认成功。只允许从具有成功工具证据的已结束任务生成可复用方案。保存的方案按适用场景、解决方法与验证展示，可展开当前或其他会话的来源任务，不再依靠轮次 ID 辨认任务。模型提取和按工作区复用规则沿用原机制。

目标管理提供“本会话目标”下拉框，根据持久化 goal_status 执行事件汇总历史目标，按名称、状态和北京时间选择，一次只展示一个目标。历史目标只读，控制按钮仅作用于当前目标；新建目标自动选中。旧的 active 快照在目标已被替换后显示“已替换”。

输入框 Goal 按钮支持选中/关闭：选中后直接发送消息即可启动 Goal，在本次任务结束时由独立判断器检查目标。右侧验收条件选填，未填写则以消息本身为目标；消息和附件仍按原流程交给 Agent。取消选中后发送普通消息，不会挂接此前目标；显式 /goal 命令保持原行为。


经验总结通过 POST /experiences/jobs 提交后由后端独立运行，立即返回任务记录；刷新或离开页面不取消总结。GET /experiences 返回 experiences 与持久化 jobs，页面自动恢复并轮询待完成任务。每次可总结最多 3 条独立经验，重点包含已解决问题、原因、步骤和验证；同一会话可从不同任务积累多条。方案卡片可单条确认删除，删除后不再检索。服务重启/停止会把未完成任务标为中断，可手工重新生成，不会自动重复消耗模型用量。

经验管理支持总结方向 focus（最多 2000 字符），可结合单个任务，或选择当前会话已完成任务整体定向总结。只填写方向、不选择任务时默认总结整个当前会话。后台任务保存方向，去重按范围、来源任务和方向判断；每条经验的证据映射回真实来源任务，没有相关已验证内容时不会补写通用知识。

左侧新增独立“经验管理”页面：可选择来源会话对应的工作区，搜索、筛选经验，完整查看适用场景、解决方法、工具证据与来源，启停或单条删除。右侧经验栏保留总结输入与后台进度，并提供进入完整管理页的入口。

经验管理来源支持“全部会话”，通过 /api/experiences 汇总数据库中各工作区已保存的经验，每条共享记录只显示一次；卡片标注来源会话，可查看来源、启停或删除。选择单个会话时仍按其当前工作区筛选。此全局管理入口不改变 Agent 按工作区检索经验的范围。

界面预览改为 HTML 页面下拉选择，列出当前会话工作区中可用的 HTML/HTM（包含嵌套目录和构建产物），优先显示本会话生成、修改或读取的文件。列表跳过内部目录和链接，扫描最多 20,000 项、列出最多 1,000 个入口，达到限制会提示。预览使用 100% 宽高铺满可用区域，以原始比例显示、无需固定宽度或缩放并始终支持点击标注，不再提供手机/平板尺寸及交互/标注切换。标注展示及批量提交按当前预览页面过滤。

经验管理使用紧凑摘要卡片，仅展示标题、简短适用场景、启用状态与证据数量；点击后以和工具/技能一致的详情弹窗查看完整方法、来源任务、工具证据，并进行启停或删除。

会话记忆中的备忘录支持手动编辑、保存、取消和重新载入，最多 8000 字符，空内容可清空。保存到当前会话并供后续主 Agent 请求使用；运行期间暂不可保存。接口 PUT /api/sessions/{session}/memory 接收 content 和原始 expected，通过事务比较原内容，冲突时返回 409，保留编辑草稿以免覆盖 Agent 或其他页面的更新。

任务管理按用户消息到 Agent 结束的一轮交互分组，显示用户需求及本轮创建、更新、查看的任务。已有任务在后续轮次继续更新时，两轮分别保留各自状态快照；无法追溯来源的旧任务单独列为历史任务。

# 简历与面试表述

## 项目条目（基于当前已实现版本）

**E_coder｜个人编程辅助 Agent 工作台**  
Python · FastAPI · SSE · SQLite · Pydantic · JavaScript · uv

- 设计模型驱动的多轮工具调用运行时，统一 15 个工具的参数校验与能力描述，实现文件操作、代码搜索、任务依赖管理、Skill 按需加载、独立上下文的单层子 Agent 委派，以及按会话隔离的持久化 Cron 调度。
- 实现文件 diff 与命令逐次审批、审批超时及文件快照冲突检测，让代码修改可审阅；覆盖路径边界、审批拒绝、取消和依赖状态等关键行为测试。
- 通过 SQLite 持久化消息和执行事件，结合 SSE 实现流式对话、工具执行可视化、刷新恢复与事件导出；以完整对话轮次整理上下文，保持工具调用与结果配对。

可以根据版面压缩为两条。完成真实模型和真实项目验证之后，再补充具体任务、成功率和数据规模。目前不声称已有模型效果提升或用户规模。

## 面试中应解释清楚

1. **为什么不用 Agent 框架？** 第一版目标是把循环、上下文、权限和事件生命周期实现清楚。模型协议适配器单独抽出，工具元数据统一管理，便于替换与测试。
2. **Skills 为什么不全部放系统提示词？** 索引用于路由，正文仅在需要时加载，减少无关上下文；当前尚无 token 节省量实测。
3. **如何防止工具对话损坏？** 按完整 user-turn 裁剪；取消/异常/重启时补齐缺失的 tool result。
4. **审批和沙箱区别？** 审批是授权，路径解析限制专用文件工具；已批准命令仍有用户权限，后续需要 OS 进程/容器隔离。
5. **为什么执行与 SSE 分离？** 页面断开无需中止任务；已落库事件可按 seq 恢复。当前单进程运行，多 worker 需要外部队列和共享审批状态。
6. **你的工作与参考项目区别？** 参考教材中的机制，重新实现前后端；增量集中在事件回放、统一能力描述、可审批 diff 和快照冲突检查。应主动说明参考来源。
